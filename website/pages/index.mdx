<section class="home-section" aria-labelledby="anatomy-title">
  <header>
    <span class="home-eyebrow">How a .blend file is built</span>
    <h2 id="anatomy-title">A memory dump with a map</h2>
    <p>Blender writes its in-memory structs to disk almost unchanged. A header in front of every block says where the block came from, and the DNA1 block describes the layout of every struct type. The <a href="/spec/index.html">specification</a> covers each part byte by byte.</p>
  </header>
  <FileAnatomy />
</section>

<section class="home-section" aria-labelledby="pointers-title">
  <header>
    <span class="home-eyebrow">How data is connected</span>
    <h2 id="pointers-title">Pointers are saved addresses</h2>
    <p>A struct points at another by the memory address it had when Blender saved. Every block header records that address, so following a pointer means finding the block with the same <code>old</code> value.</p>
  </header>
  <PointerHops />
</section>

<section class="home-section" aria-labelledby="inside-title">
  <header>
    <span class="home-eyebrow">What data is inside</span>
    <h2 id="inside-title">More than the scene</h2>
    <p>A file holds the whole state Blender had when saving: windows, workspaces and editors, the type catalog, a thumbnail, and the scene itself. <a href="/spec/08-datablocks.html">08 Datablocks</a> lists where common values live.</p>
  </header>

</section>
